# EDR / BRL 9501 engineering report — 2026-09-07

## Executive result

The project has been moved from a simple homeowner screening calculator toward an attestation-ready engineering structure.

**It is not yet BRL 9501 conformant or attestable.**

The decisive reason is not lack of a test harness. The current calculation kernel is still a screening model and the official ISSO 54 reference-result workbook is not incorporated into the repository. It would therefore be misleading to report numerical EDR passes.

The harness is deliberately fail-closed: executable screening cases are marked `EXECUTED`, but EDR conformance remains `BLOCKED` until the controlled reference results and complete NTA implementation are available.

## Standards basis reviewed

The public historical ISSO 54 version 2.0 document states that it defines EDR tests for NTA 8800 calculation programs, covering both housing and utility buildings. It lists 219 dwelling tests and 58 utility tests in the published test inventory, 277 total, and states a historical rejection criterion of more than ±1.0% from the reference result.

For the current 2026 regime, the Dutch regulatory framework requires energy-label calculation software to be attested according to BRL 9501. The current regulation also identifies NTA 8800:2025+C1:2026 as the applicable calculation method and the current BRL 9501 as the software quality framework.

## What was executed

The EDR harness executes these publicly documented historical reference-building variants through the present screening kernel:

- EPW001 — reference dwelling;
- EPW002a — older/poor insulation and single glazing;
- EPW002b — 1995 building with Rc 2.5 envelope;
- EPW003c — roller-shutter resistance case;
- EPW004a–g — orientation variants.

The harness verifies that the screening kernel produces finite numerical results and records those results. It does **not** compare them against the official EDR result workbook because that workbook is a separate controlled document.

## Why the test suite cannot yet be called a pass

A BRL 9501 EDR test is not simply “run a plausible building through the calculator.” The attestation process requires the prescribed input and the prescribed reference output/band for every applicable test/subtest. The attestation institution independently samples the calculation results and requires them to fall within the applicable bands.

The present kernel lacks complete implementations for, among other things:

- ground/adjacent boundary calculation;
- detailed solar and shading treatment;
- thermal bridges;
- NTA infiltration and airtightness rules;
- complete ventilation variants and auxiliaries;
- complete emission/distribution/control models;
- NTA heat-pump generation calculations and declaration interpolation;
- complete DHW calculations;
- complete cooling calculations;
- complete renewable-energy accounting;
- all current primary-energy factors and reporting;
- current 2026 output and rounding requirements.

Therefore the correct current status is **engineering prototype / screening**, not attestation candidate.

## CI

A GitHub Actions workflow runs `npm test` on every push and pull request. At the time this report was written, the newest workflow run was still in progress, so no claim of a completed CI pass is made here.

## Required next gates

1. Obtain the current controlled ISSO 54 EDR fixtures and reference results.
2. Freeze the current NTA 8800:2025+C1:2026 reference data.
3. Replace the screening calculation chain with a complete NTA implementation.
4. Implement all EDR input structures.
5. Execute every applicable EDR test and store immutable evidence.
6. Require every result to fall inside its prescribed band.
7. Establish independent calculation-code review.
8. Complete the quality-system records and release controls.
9. Approach an accredited BRL 9501 attestation institution for formal assessment.

## Conclusion

The project is now structured in the way an eventual BRL 9501 software project should be managed: controlled requirements, controlled releases, EDR fixtures, fail-closed test reporting, and a documented quality system.

The remaining work is substantive calculation engineering, not cosmetic compliance documentation. In particular, it would be a mistake to label the current screening kernel “BRL 9501 ready” merely because the quality manual exists.
